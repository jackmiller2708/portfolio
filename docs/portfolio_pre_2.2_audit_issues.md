## P2 — Significant UX friction

| #     | Page           | Issue                                                                            | Evidence from live DOM                                                                                                                                                                                                                                                                                                                                                                   |
| ----- | -------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P2-01 | Services       | **Content duplicated verbatim across two sections**                              | The three services appear in full in the top card grid, then appear again word-for-word in the "Concrete outputs by service" section below. The second section relabels "Client pain" as "Evidence" and "Outputs" as "Recommendation" but the actual text is identical. A visitor who reads the first section gains nothing from the second.                                             |
| P2-02 | Home           | **Credibility strip reads as metadata, not a visual component**                  | "Primary focus / Angular systems", "Engagement shape / Scoped diagnostics", "Delivery style / Evidence first" renders as three stacked label + bold text + description rows at the same visual density as everything below. No icons, no horizontal layout, no visual differentiation from body content. First content after the hero, should be the fastest-reading signal on the page. |
| P2-03 | Home           | **"Delivery style / Evidence first" section announces rather than demonstrates** | A row that describes the methodology in prose. The principle of being evidence-first should be communicated by the structure of the case studies and map — not stated in a feature list before the reader has seen any evidence.                                                                                                                                                         |
| P2-04 | Sitewide       | **No visual breaks between sections**                                            | Every section runs directly into the next separated only by a heading. No background alternation, no surface depth variation, no horizontal dividers with breathing room. On mobile this produces a continuous undifferentiated wall of content.                                                                                                                                         |
| P2-05 | Sitewide       | **Accent color used only on CTA buttons**                                        | The pink accent (`#E0478B`) appears exclusively on two CTA buttons. Severity badges, section labels, diagram node labels, and the system map connectors are all missed opportunities to pull the eye toward content rather than only toward conversion.                                                                                                                                  |
| P2-06 | Home           | **Diagnostic panel options have no visible affordance of interactivity**         | The four pain selector options render as plain rows. Without a visible border, hover state, or selection indicator in the static render, a visitor scanning the page has no signal that these are interactive. The most strategically important interaction on the site is invisible until a visitor happens to hover or tap.                                                            |
| P2-07 | Home + Contact | **Diagnostic panel appears on two pages without differentiation**                | The same panel structure, same four options, and same recommended path layout appears on both the home page and the contact page with only minor copy differences. Without visual or contextual distinction it reads as an implementation bug rather than a deliberate echo.                                                                                                             |
| P2-08 | Home (mobile)  | **System map SVG not rendering visibly on mobile**                               | The screenshot shows "The architecture in context" section rendering as: an italic caption, two toggle labels, a plain-text description, then a text list of node relationships. No visual diagram is present. The SVG/canvas either fails to load or is invisible at this scroll position on mobile.                                                                                    |

## P3 — Completeness and polish

| #     | Page               | Issue                                                    | Evidence from live DOM                                                                                                                                                                                                                                                                                                          |
| ----- | ------------------ | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P3-01 | Contact            | **Form fields have no persistent labels**                | All form fields (Name, Email, Product or company context, Angular version, Team size, Timeline, Budget comfort, Main pain, Engagement type) render with placeholder text only. Placeholders disappear on focus. A mobile visitor partway through a long form loses context for what each field was asking. WCAG non-compliance. |
| P3-02 | All pages          | **Navigation has no active/current page indicator**      | Nav links (Services, Case Studies, Lab, Sample Audit, About, Contact) have no visible selected or current state. The nav looks identical on every page.                                                                                                                                                                         |
| P3-03 | Lab                | **Page too sparse to justify its own nav slot**          | Three entries visible in the DOM (a fourth is referenced but may be JS-dependent). No intro paragraph, no category grouping, no framing of what the lab is. The nav label "Lab" implies a considered creative space — the page is a short unsupported list.                                                                     |
| P3-04 | About              | **No philosophy statement — only working style bullets** | The About page has two bullet-list sections ("Small diagnostics before large prescriptions", "Maintainability as visible decisions") and a communication block. Every sentence describes a behaviour or process. No sentence on this page could only have been written by a specific person with a specific perspective.        |
| P3-05 | About              | **Placeholder email in production**                      | The email listed is `hello@example.com` — a placeholder that was never replaced with a real contact address. Appears in both the About page body and the Contact page fallback.                                                                                                                                                 |
| P3-06 | Contact            | **No framing sentence before the intake form**           | The form opens immediately after the diagnostic panel with no sentence that sets the register or tells the visitor what the form is for or what happens after submission.                                                                                                                                                       |
| P3-07 | Home               | **Hero line is passive and interchangeable**             | "I make complex frontend systems explicit, safer, and easier to evolve." describes an outcome accurately but has no situation the reader is in, no personality, and no sentence that could only belong to this specific person. It is a competent positioning statement, not an identity.                                       |
| P3-08 | Case studies index | **Page subtitle uses "proof" as the primary framing**    | Live subtitle: "Redacted and synthetic proof of constraints, decisions, tradeoffs, and outcomes." Sets an adversarial register before a single case study is read.                                                                                                                                                              |
| P3-09 | Sitewide           | **All animations snap — no easing or motion character**  | Every transition and state change cuts or uses default linear/ease CSS. No entrance animations, no spring interactions, no scroll reveals. The site feels like a static document rather than an interactive application despite having interactive components (diagnostic panel, system map toggle, stepper).                   |
| P3-10 | Sitewide           | **Dark/light mode has no transition**                    | Theme toggle switches the site instantly with no crossfade. Abrupt full-page color swap at the point of interaction.                                                                                                                                                                                                            |
| P3-11 | Sitewide           | **No personality or point of view anywhere on the site** | The site communicates services and process accurately but no page contains a sentence that reveals how this person specifically thinks about systems problems. The identity is defined entirely by service categories and process descriptions — not by character or perspective.                                               |

## Notes on scope

This list reflects only what was present in the live built site before any spec or design work in this session. Issues introduced or resolved by v2.1 or v2.2 spec documents are not counted here — those specs describe the intended fix state, not the current state.

The placeholder email (P3-05) is the only issue on this list with a security/privacy dimension — it means no real contact inquiries are being received regardless of how well the rest of the site performs.
